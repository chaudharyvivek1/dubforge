# Code of conduct

## The short version

Be decent. Assume competence. Argue about the code, never about the person.

## What is expected

* **Technical honesty.** If a change makes a failing dub look successful, it will be
  rejected — that is the one rule this project holds above all others.
* **Good-faith disagreement.** "This will break on a mono source, here is the test"
  is a contribution. "This is obviously wrong" is not.
* **Patience with beginners.** A school teacher running `dubforge doctor` for the first
  time is exactly who this tool is for. Their question is not stupid.
* **Credit where it is due.** New adapters, better timing constants and platform fixes
  get named in the changelog.

## What is not tolerated

* Harassment, insults, or personal attacks of any kind.
* Discrimination on the basis of caste, religion, region, language, gender, sexuality,
  disability or age. This project exists partly *because* Indian languages are
  under-served; contempt for the people who speak them has no place here.
* Sexualised content or attention, in any context.
* Publishing anyone's private information.
* Using the project, its issues or its discussions to help build non-consensual voice
  impersonation. Consent is a hard line — see [docs/security.md](docs/security.md).

## Scope

Issues, pull requests, discussions and any space where you are representing the
project.

## Enforcement

Report a problem to the maintainer, [Vivek Chaudhary](https://github.com/chaudharyvivek1),
by opening a confidential report through GitHub's
[report abuse](https://github.com/contact/report-abuse) flow or by email at the address
on his GitHub profile. Reports are read by him alone.

Responses, in order of severity: a private word, a public correction, a temporary
block, a permanent ban. A maintainer who is the subject of a report does not decide it.

This is a small project maintained by one person. Enforcement will be proportionate and
occasionally slow; that is not indifference.
